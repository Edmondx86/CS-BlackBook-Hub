# <span style="color: rgb(var(--brand));">ICMP 协议</span>

### 前面几张卡讲的都是“怎么把包送到目的地”，可网络这东西从来不会一帆风顺：主机不可达、TTL 耗尽、端口没人监听……出了问题总得有人报信吧。负责这个活儿的，就是 <strong>ICMP（Internet Control Message Protocol，因特网控制报文协议）</strong>——网络层的“报信员”，专门在主机和路由器之间传递网络层的差错与控制信息。

# <span style="color: rgb(var(--brand-dark));">5.6 ICMP：网络层的“报信员”</span>

## <span style="color: rgb(var(--brand-dark));">报文长什么样</span>

### ICMP 报文的结构非常朴素，开头就三个字段：

* 类型（type）：这是哪一类 ICMP 报文，比如 8 表示回显请求、3 表示目的不可达。
* 代码（code）：同一类型下的细分原因，比如“目的不可达”到底是网络不可达还是端口不可达。
* 检验和（checksum）：用来校验报文有没有在传输中损坏。

### 后面还跟着 4 个字节（内容随 type/code 变化），以及**引起这个 ICMP 报文的那份原始 IP 数据报的首部和前 8 个字节数据**。为什么要捎上原始数据报？因为报信总得说清“是谁出的事”——发送方靠这段数据才能认出是哪条连接、哪个应用出了问题。

### 这里有个特别容易误解的点：**ICMP 报文并不是直接扔到链路上传输的，它是被封装进 IP 数据报里当载荷发出去的**（IP 首部的协议号填 1）。所以严格来说，ICMP 属于网络层协议，而不是运输层协议——尽管它看上去有点像“网络层自带的小信使”。

## <span style="color: rgb(var(--brand-dark));">两类用途：差错报告与查询</span>

### ICMP 报文可以分成两大阵营：

1. 差错报告（error reporting）：设备发现出问题了，回头给源主机报个信。最常见的有三种：
   * 目的不可达（type 3）：路由器找不到去目的地的路，或者目的主机上压根没有进程监听那个端口（code 3）。
   * 时间超时（type 11）：数据报的 TTL 减到 0 被丢弃（code 0），或者分片重组超时（code 1）。
   * 参数问题（type 12）：IP 首部里有字段非法，路由器看不懂。
2. 查询报文（query）：主动打听信息，通常成对出现：
   * 回显请求（type 8）/ 回显应答（type 0）：你问我答，最典型的用途就是 `ping`。
   * 路由器请求（type 10）/ 路由器通告（type 9）：主机主动询问“这个网段里都有哪些路由器”。

### 有意思的是，ICMP 差错报文并不会“逢错必报”，它有几条明确的克制规则：

* 不为 ICMP 差错报文本身再发差错报文——否则一个错误就能引发无穷无尽的互相报错。
* 不为非第一个分片发差错报文——分片信息不全，报了也没用。
* 不为多播 / 广播地址的数据报发差错报文——一个人出错，没必要惊动全城。

### 这些规则背后的思路很统一：**报错是为了帮发送方解决问题，而不是制造更多麻烦。**

## <span style="color: rgb(var(--brand-dark));">两个家喻户晓的应用</span>

### ICMP 平时默默无闻，却撑起了你天天在用的两个命令：

* **`ping`**：向目标发一个 **type 8 回显请求**，对方（如果还活着、并且没屏蔽 ICMP）回一个 **type 0 回显应答**。一来一回，你就能算出往返时延 RTT，顺便确认“对面还在不在”。
* **`traceroute`（Windows 上叫 `tracert`）**：这个更巧妙。它先把 TTL 设成 1 发出探测包，第一跳路由器把 TTL 减到 0、扔掉包并回一个 **type 11 超时报文**，于是你就知道了第一跳是谁；接着把 TTL 设成 2、3、4……逐跳把整条路径“钓”出来。等包终于到达目的主机、却撞上一个没人监听的端口时，对方会回一个 **type 3 且 code 3 的端口不可达**，这就等于告诉 traceroute：到终点了。

> 说白了，`traceroute` 就是靠“故意让包死在每一跳”来摸清整条路径的——一个把差错报告反过来当探测工具用的经典操作。

## <span style="color: rgb(var(--brand-dark));">顺带一提：ICMPv6</span>

### 到了 IPv6 时代，ICMP 非但没有退休，任务反而更重了。`ICMPv6` 除了继承差错报告，还承担了地址自动配置、邻居发现（Neighbor Discovery，接替了 ARP 的活儿）等一大堆工作，成了 IPv6 不可或缺的组成部分。所以别把 ICMP 当成一个“可选的小工具”，它是网络层正经的组成部分。

### 顺便提一句：本章的 Wireshark 实验刚好就是拿 ICMP 开刀——亲手抓一次 `ping`，你就能在屏幕上看到 type 8 和 type 0 你来我往，比看十遍文字都管用。

## 所以，ICMP 就是网络层的报信员：用 type/code 说清“哪里出了什么错”，用回显与超时报文撑起 `ping` 和 `traceroute`。下一张卡我们换个视角，看看这一大堆设备平时是怎么被监控和配置的——也就是网络管理。
