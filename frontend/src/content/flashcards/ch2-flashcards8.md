# <span style="color: rgb(var(--brand));">网络套接字编程 (Socket)</span>

### 前面学了 HTTP、DNS、邮件……这些都是别人写好的“现成应用”。但如果你想亲自动手，比如写一个聊天小程序、一个多人在线小游戏，你手里最核心的那件工具，就是套接字（Socket）。它是应用进程与传输层之间的一扇“门”——你通过它把数据塞进网络，也通过它把网络里的数据取出来。这一节就带你亲手摸一摸这把“网络瑞士军刀”。

# <span style="color: rgb(var(--brand-dark));"> 2.9 套接字是什么？ </span>

### 还记得第一章埋的“邮政服务”那个比喻吗？应用进程想往另一个进程发数据，不能把信“顺窗户撇出去”，必须通过套接字这个“接口”来收发。套接字本质上就是应用层和传输层之间的编程接口（API），程序员只需要调用它提供的函数，就能让数据在网络上跑起来，而不用关心底层的 IP、路由这些“脏活累活”。

### 因为传输层有两位主角，套接字编程也分两大流派：`UDP Socket`（无连接，发数据报）和 `TCP Socket`（面向连接，传字节流）。下面分别看看。

## <span style="color: rgb(var(--brand-dark));"> 2.9.1 UDP Socket 编程：发快递，不问送达 </span>

### UDP 是“无连接”的，发数据前不用先和对方“握手建连”。用 UDP 编程，就像发快递：你在包裹上写好“收件地址（IP）”和“收件人（端口号）”，直接扔给邮局就行，至于对方收没收到、到没到，你一概不管。

### UDP 编程的关键函数就两个：

1. **`sendto()`**：发送方调用，把一段数据（`datagram`）连同目标地址、端口一起发出去。
2. **`recvfrom()`**：接收方调用，守在某个端口上“收包裹”，收到后还能知道是谁寄来的（附带了源地址）。

### 它还有个重要特性：数据报边界清晰。你发一个包，对方收到就是一个完整的包，不会跟下一个包“糊”在一起。适合那些“丢一两个包无所谓、但要求快”的应用，比如实时语音、在线游戏、DNS 查询。

## <span style="color: rgb(var(--brand-dark));"> 2.9.2 TCP Socket 编程：打电话，先建连再聊 </span>

### TCP 是“面向连接”的，像打电话：先拨号（建立连接），对方“喂”一声（确认接通），然后才开始聊。在 TCP 里，这个“拨号-应答”就是大名鼎鼎的三次握手（three-way handshake）。

### TCP 编程分“客户端”和“服务器”两套动作：

服务器端（先“摆摊”等客）：
1. `socket()` —— 先开一个“摊位”（创建套接字）。
2. `bind()` —— 给摊位挂上“门牌号”（绑定 IP 和端口）。
3. `listen()` —— 开始“竖起耳朵”监听，准备接客。
4. `accept()` —— 有客户端敲门（连接请求）了，接受它，并专门为这个客户端开一条“专用通道”（新的套接字）。
5. 通过这个专用通道 `read()/write()` 收发数据。

客户端（“上门找店”）：
1. socket() —— 也开一个套接字。
2. `connect()` —— 按服务器地址“拨号”，发起三次握手。
3. 连上后，用 read()/write() 收发数据。

### TCP 和 UDP 编程有个关键区别：TCP 传的是字节流（byte stream），没有消息边界。你 `write()` 两次，对方可能一次 `read()` 就全读到了，也可能分三次才读完——就像水龙头流水，没有“一杯一杯”的分界。所以用 TCP 编程时，得自己想办法在数据里“标出边界”（比如约定每条消息多长，或加个结束标记）。

### 收尾打个比方：UDP 像寄明信片，快、简单、不保证到；TCP 像打电话，慢一点、要建连，但可靠、有序、不丢。选哪个，全看你做的应用“更怕慢”还是“更怕错”。
