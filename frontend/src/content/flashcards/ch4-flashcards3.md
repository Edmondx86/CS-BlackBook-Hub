# <span style="color: rgb(var(--brand));">IP 协议</span>

### woohooo！终于来到这一章的重头戏了，那就是因特网网络层的关键方面和著名的网际协议（IP）。如今有两个版本的IP正在使用，一种是IPv4，另一种是IPv6，而后者已经快要替代IPv4一统江山了。我们主要要了解的是因特网编址，掌握IP编址就是掌握因特网的网络层。

# <span style="color: rgb(var(--brand-dark));">4.3.1 IPv4数据报格式</span>

### IPv4的数据报中的关键字如下：
* 版本号
* 首部长度
* 服务类型

* 寿命
* 协议

* 源和目的IP的地址
* 选项
* 数据（有效载荷）

# <span style="color: rgb(var(--brand-dark));">4.3.2 IPv4编址</span>

### 在讨论IP编址之前，先简述一下主机和路由器连入网络的方法。一台主机通常只有一条链路连接到网络（现实并非如此，一台电脑由多张网卡是常有的事，这里方便理解当成理想状态），当主机中的IP想要发送一个数据报的时候，它就在该链路上发送。主机与物理链路之间的边界叫作`接口（interface）`。因为路由器的职责是从链路上接收数据报并从某些其他链路转发出去，所以路由器必须拥有两条以上的链路和它相连。路由器和它任意一条链路之间的边界也叫接口。说白了就是一台路由器由多个接口，每个接口都有其链路。IP要求每台主机和路由器接口都有自己的IP地址。因此，从技术上讲，`一个IP地址与一个接口相关联`,`一个IP地址与一个接口相关联`,`一个IP地址与一个接口相关联`，而不是与包括该接口的主机或者路由器关联。

### 每个IP地址32比特，也就是4字节。这些地址通常按照`点分十进制记法`书写，为什么呢？因为二进制数你记不住，就这么简单。比如：最简单的127.0.0.1就是一个本机IP地址。在全球因特网中，每台主机和路由器上的每个接口都必须有一个全球唯一的IP地址。然后IP的选择并非“随心所欲”的，一个接口的IP地址的一部分需要由其连接的子网来决定。

### 因特网的地址分配策略被称为`无类别域间路由选择（Classless Interdomain Rounting ，CIDR）`。CIDR将子网寻址的概念一般化了，用子网寻址时，IP地址被分为两部分，并且也具有a.b.c.d/x的形式，其中的指示了地址第一部分中的比特数。这里的x最高比特构成了IP地址的网络部分，并且经常被称为`前缀`，一个组织通常被分配一块连续的地址，即拥有相同的前缀。在这种情况下，该组织内部的IP地址将共享共同的前缀。一个地址的剩余32-x比特可认为是用于区分组织内部的设备的，当组织内部路由器进行转发分组时这些比特几回派上用场。

### 值得一提的是另一种类型的IP地址，即`广播地址255.255.255.255`。顾名思义，当一台主机发送的目的地址为255.255.255.255的数据报时，该报文会像广播一样发送给该网络中的所有主机。

# <span style="color: rgb(var(--brand-dark));">4.3.3 获取地址：动态主机配置协议（DHCP）</span>

### 既然一个接口需要一个IP地址才能正常工作，那这个IP地址到底是怎么来的呢？有两种办法：一种是网络管理员手工硬编码配置（比如服务器IP）；另一种就是更常用的`即插即用（plug-and-play）`机制，也就是通过`动态主机配置协议（DHCP）`自动获取。

### DHCP允许主机在连接到网络时自动获取一个IP地址。它可以配置为主机每次连接时获得同一个IP地址，也可以为每台主机分配一个`临时的IP地址（租用地址）`。DHCP还能够为主机提供第一跳路由器地址（默认网关）、DNS服务器的IP地址以及网络掩码等额外信息。

### DHCP的工作流程可以细分为以下4个步骤：
* **DHCP服务器发现（DHCP server discovery）**：新到的主机发送`DHCP discover`报文。因为主机还不知道DHCP服务器的IP，所以目的IP填为广播地址`255.255.255.255`，源IP填为`0.0.0.0`。
* `DHCP服务器提供（DHCP server offer）`：DHCP服务器收到发现报文后，用`DHCP offer`报文响应。由于子网中可能有多个DHCP服务器，因此主机可能会收到多个提供报文。
* `DHCP请求（DHCP request）`：新到达的主机从一个或多个服务器提供中选择一个，并向选中的服务器发送`DHCP request`报文，响应其配置参数。
* `DHCP ACK（DHCP消息确认）`：服务器用`DHCP ACK`报文对请求报文进行响应，证实所要求的参数已被确认，此时主机正式获得了该IP地址。

# <span style="color: rgb(var(--brand-dark));">4.3.4 网络地址转换（NAT）</span>

### 随着连入因特网的设备呈指数级增长，IPv4的32比特地址空间很快就被消耗殆尽。为了缓解这个问题，`网络地址转换（Network Address Translation，NAT）`应运而生。NAT路由器的出现，使得一个本地家庭网络或者小型公司网络只需要向ISP申请`一个`全球唯一的公网IP地址即可。

### NAT的核心原理依赖于`NAT转换表（NAT translation table）`。对于专用网络内部的主机发出的分组，NAT路由器不仅改变其源IP地址（换成公网IP），还会改变其源端口号（换成路由器自身分配的新端口号），并在转换表中记录这一映射关系：

### NAT转换表的作用机制如下：
* `出站分组`：当私网主机（如192.168.0.3:3345）向公网发送分组时，NAT路由器拦截该分组，将其源IP换成公网IP（如172.38.1.5），源端口换成新端口（如5001），并在转换表中增加一条映射项。
* `入站分组`：当公网服务器发回响应（目的地址为172.38.1.5:5001）时，NAT路由器查找转换表，将其替换回私网IP和原始端口（192.168.0.3:3345），然后再转发给私网内部的主机。

> 虽然NAT极大地缓解了IPv4地址枯竭的问题，但在学术界和工程界也引发了不小争议：首先，它打破了端到端通信的基本原则；其次，路由器本属于网络层设备，却修改了传输层的端口号（破坏了分层原则）；最后，NAT也阻碍了P2P（对等网络）应用的发展。

# <span style="color: rgb(var(--brand-dark));">4.3.5 IPv6</span>

### 尽管NAT能够在短期内“续命”，但IPv4地址空间的枯竭终究不可逆转。因此，设计一个具有更大地址空间的新版本协议势在必行，这就是`IPv6`。IPv6将地址长度从32比特直接扩展到了`128比特`，确保了在可预见的未来再也不会出现地址不够用的情况。

### IPv6数据报的关键改进字段与格式如下：
* `扩充的地址能力`：地址长度从32位增加到128位，引入了`任播地址（anycast address）`。
* `简化且定长的40字节首部`：许多IPv4可选字段被移除或变为扩展首部，使得路由器处理数据报更加迅速。
* `流标签与优先级`：`Flow Label`和`Traffic Class`字段用于支持QoS（服务质量），给特定流（如实时音视频）提供特殊处理。
* `移除了首部检验和`：由于数据链路层和传输层大多已经提供了检验和，网络层不再重复计算，提高了转发效率。
* `移除了分片/重新组装`：分片只能由源主机进行，中间路由器若遇到过大的分组则直接丢弃并返回ICMPv6“分组过大”消息。

> 目前全球网络正在经历从IPv4向IPv6过渡的长久阶段。最常用的过渡技术是`隧道技术（tunneling）`：当两个IPv6节点之间隔着一堆IPv4路由器时，我们可以将整个IPv6数据报作为有效载荷“套”在一个IPv4数据报内部进行传输，等穿过IPv4网络到达另一个IPv6节点后再解封装。
