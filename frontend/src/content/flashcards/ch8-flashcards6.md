# <span style="color: rgb(var(--brand));">IPsec、VPN 与防火墙</span>

### 最后一张卡片了！TLS 保护的是单个应用的连接，可如果整个公司的内网要通过公网互连呢？总不能给每台机器、每个应用都改一遍代码。这就需要把安全下沉到网络层——这就是 `IPsec`。而如果把守在网络边界、决定“谁能进来”的，则是防火墙和入侵检测系统。这三样凑齐，网络安全的版图就算完整了。

# <span style="color: rgb(var(--brand-dark));">8.7 网络层安全：IPsec 与 VPN</span>

## <span style="color: rgb(var(--brand-dark));">把加密下沉到 IP 层</span>

### TLS 的位置在运输层之上，所以它只能保护支持 TLS 的那些应用。而 `IPsec` 的做法是：在网络层把整个 IP 数据报保护起来。这样一来，上层的 TCP、UDP、HTTP、DNS……统统自动获得保护，应用完全不用改一行代码。

### IPsec 提供两个协议：

* AH（Authentication Header，鉴别首部）：只提供鉴别和数据完整性，不加密。用得较少。
* ESP（Encapsulating Security Payload，封装安全载荷）：鉴别 + 完整性 + 机密性全包，是实际部署中的主力。

### 通信双方在传输数据前，要先协商出一个安全关联（SA, Security Association）——本质上一份约定，规定了用哪种算法、用哪把密钥、采用什么模式。这个协商由 IKE（Internet Key Exchange） 协议完成。

## <span style="color: rgb(var(--brand-dark));">隧道模式与 VPN</span>

### IPsec 有两种工作模式，隧道模式（tunnel mode） 是构建 VPN 的关键：

1. 原始 IP 数据报整个儿（包括原来的 IP 首部）被当作载荷。
2. 在它外面套上一个新的 IP 首部，指向隧道另一端的 IPsec 网关。
3. 中间经过公网的路由器只看得到外层首部，**看不到内层的真实源/目的地址，也看不懂内容**。

### 于是，一家公司在北京和上海各有办公网，两个网关之间用 IPsec 建一条隧道，两端内网的机器就像坐在同一个机房里——可以互相访问、跑内网服务，而中间的流量跑在公网上却是加密的。这就是 **VPN（Virtual Private Network，虚拟专用网）**：**用公网的线路，造一条私网的通道**。

### 顺便说一句，隧道模式和你第四章见过的“IPv6 隧道”是同一个套娃思路——把整个数据报当成载荷塞进另一个数据报里，只不过这次套上去的外壳顺便还加了密。

# <span style="color: rgb(var(--brand-dark));">8.9 运维安全：防火墙与 IDS</span>

## <span style="color: rgb(var(--brand-dark));">防火墙：把守大门</span>

### 防火墙（firewall） 位于内网与外部网络之间，根据规则决定放行还是丢弃流量。常见的有三类：

* **无状态分组过滤器（stateless packet filter）**：逐个分组独立判断，只看首部字段——源/目的 IP、源/目的端口、TCP 标志位、ICMP 类型等。比如“只允许外部访问 80 和 443 端口”“禁止所有 ICMP 进来的包”。它简单高效，但看不到连接状态，容易被绕过（比如攻击者伪造一个看似是内部响应的 ACK 包）。
* **有状态分组过滤器（stateful packet filter）**：跟踪 TCP 连接的状态。它维护一张连接表，只有在表中存在对应合法连接的包才放行。这样“外部的 ACK 包”就不再能骗过它了——因为它知道根本没人发起过那条连接。
* 应用网关（application gateway）：工作在应用层，比如一个 HTTP 代理。它能看到完整的应用层内容，可以按 URL、按用户身份做精细控制，甚至可以过滤关键字。代价是性能开销大、每支持一个新应用就要写一份专用代码。

### 在实践中，这三种常常组合使用：边界上先做无状态过滤挡掉明显的垃圾流量，再做有状态过滤挡住异常连接，最后由应用网关对关键业务做细粒度管控。

## <span style="color: rgb(var(--brand-dark));">IDS：不光挡，还要看</span>

### 防火墙只能按规则放行或丢弃，可总有一些看似合法的攻击流量——比如精心构造的、能变形绕过规则的攻击载荷。这时就需要 IDS（Intrusion Detection System，入侵检测系统）：

* 基于特征检测（signature-based）：维护一个攻击特征库（比如某种蠕虫的字节序列），发现流量匹配就告警。它准确率高、误报少，但只能抓住已知攻击。
* 基于异常检测（anomaly-based）：先学习“正常流量长什么样”，一旦出现明显偏离（比如半夜突然有主机大量外连）就告警。它有可能抓出未知攻击，代价是误报率较高——把正常业务波动也当成入侵。

### 如果设备不仅告警还直接阻断，那它就叫 IPS（Intrusion Prevention System，入侵防御系统）。它和 IDS 的区别就像“监控摄像头”和“带自动拦截的闸机”——一个只看，一个又看又拦。

## 所以，IPsec 把安全下沉到网络层、用隧道模式撑起 VPN，防火墙按规则把守边界，IDS 靠特征和异常发现异常——它们共同构成了网络安全的最后一道防线。至此，从第一章的“什么是因特网”到这里的“如何让因特网可信”，这门课的主线就彻底走完了。恭喜你通关！
