# <span style="color: rgb(var(--brand));">QUIC 协议</span>

### 学完了 TCP，你可能会吐槽：这家伙可靠是可靠，但“三次握手 + TLS 握手”要跑好几个往返才能开始传数据，也太墨迹了吧？于是 Google 搞出了 **QUIC（Quick UDP Internet Connections）**——一个**跑在 UDP 之上、却比 TCP 更快更灵活**的运输层协议，也是如今 HTTP/3 的底层。

# <span style="color: rgb(var(--brand-dark));"> 3.8.1 为什么是 UDP 而不是重新发明 TCP？ </span>

### 关键点：QUIC **构建在 UDP 之上**，但**在应用层自己实现了可靠传输、流量控制、拥塞控制**。这么做的理由很现实：

* 改动操作系统内核里的 TCP 太难、太慢，几乎不可能让全世界用户都升级；
* 而 UDP 只是个“空壳”，QUIC 想怎么玩就怎么玩，**部署在应用层**，浏览器/服务器一升级就生效。

# <span style="color: rgb(var(--brand-dark));">3.8.2 QUIC 的几大亮点 </span>

### 1. **连接建立更快**：把传输握手和 TLS 加密握手**合并**，常见情况下 **1 个 RTT 就能开始传数据**，重复连接甚至能做到 **0 RTT**。对比 TCP+TLS 通常要 2~3 个 RTT，优势明显。

### 2. **无队头阻塞（Head-of-Line Blocking）**：这是 QUIC 最聪明的地方。TCP 是一条“单行道字节流”，一个包丢了，后面所有包都得干等着它重传。QUIC 把数据拆成**多条独立的多路复用流（stream）**，某条流丢包只影响它自己，其他流照常前进。

### 3. **内置 TLS 1.3**：加密不是“外挂”而是“出厂自带”，默认全加密。

### 4. **连接 ID 与无缝迁移**：TCP 用“四元组（IP+端口）”标识连接，手机从 WiFi 切到 4G 一变 IP 就得重连。QUIC 用独立的**连接 ID**，网络切换后连接依然能**无缝延续**，刷视频不中断。

# <span style="color: rgb(var(--brand-dark));"> 一句话总结 </span>

### **QUIC = UDP 的外壳 + TCP 的可靠 + TLS 的加密 + 多流无队头阻塞 + 快速连接建立**。它把 TCP 几十年积累的经验“重新封装”了一遍，去掉了历史包袱，成了下一代互联网传输的事实标准（HTTP/3）。
