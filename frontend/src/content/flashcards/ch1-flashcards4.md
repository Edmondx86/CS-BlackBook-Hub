# <span style="color: rgb(var(--brand));">网络规则：协议</span>

### 上一节我们见识了网络核心这个“超级分拣系统”，路由器们忙前忙后地把分组像快递一样逐跳送达。但是你有没有想过一个更根本的问题：这些设备之间到底是怎么“交流”的？它们怎么知道某个分组是在打招呼还是在骂街？怎么知道什么时候该说话、什么时候该闭嘴？答案只有两个字——**协议**。

# <span style="color: rgb(var(--brand-dark));">1.6 什么是协议（Protocol）</span>

### 别被“协议”这个词唬住，它听起来高大上，其实你每天都在不知不觉地遵守。

## <span style="color: rgb(var(--brand-dark));">1.6.1 从“你好”开始：人类社会的协议</span>

### 假设作者走在大街上迎面撞见了 ROSE，热情地来了句“早上好啊！”，ROSE 大概率会回一句“早上好！”，而不是反手给你一个大比兜。为什么？因为我们俩都默认遵守着一套心照不宣的规矩：先问好，再回应。这套约定俗成的规则，就是人类社会里的“协议”。

### 再比如，ROSE 想跟网站作者通个电话，对话一定是按这个套路走的：ROSE 先说“喂？”，网站作者听到后回一句“喂？”，确认对方在线之后，正事才开始。如果 ROSE 一接起来就自顾自地飙一长串装机教程，作者还没回过神来呢，信息就全丢了。你看，连打电话都有“协议”。

## <span style="color: rgb(var(--brand-dark));">1.6.2 网络协议：机器之间的“契约”</span>

### 把上面的场景搬到网络里，就是协议的全部精髓。用学术一点的话说：`协议（protocol）`定义了在两个或多个通信实体之间交换的报文的*格式*和*顺序*，以及报文发送/接收时所要采取的*动作*。

### 说白了，协议就是“网络世界里大家公认的一套规矩”。ROSE 的电脑想给网站作者的服务器发个请求，它必须严格按照协议规定的格式去发，对方才看得懂；而对方收到后，也得按协议规定的动作来回应。没有协议，两台机器就是鸡同鸭讲——一个用 Java 的脑回路发，一个用 Python 的脑回路收，谁也读不懂谁。所以你会看到，全世界的路由器、交换机、主机，无论什么牌子、什么系统，只要都遵守 `TCP/IP` 协议族，就能互联互通。

# <span style="color: rgb(var(--brand-dark));">1.6.3 协议的三大要素</span>

### 那么一套完整的协议，到底规定了哪些东西呢？教科书把它拆成了三大要素，缺一不可：

## <span style="color: rgb(var(--brand-dark));">1.6.4 语法（Syntax）：报文长什么样</span>

### 语法规定的是报文的“长相”——数据按什么格式、什么结构来组织。就像写信，你得先写收件人、再写正文、最后落款，顺序不能乱；网络报文也一样，哪个字段放源地址、哪个字段放目的地址、哪个字段放校验和，都有严格的规定。语法回答的问题是：“这一串 0 和 1 该怎么排？”

## <span style="color: rgb(var(--brand-dark));">1.6.5 语义（Semantics）：每个字段是什么意思</span>

### 语法只说了“长什么样”，但光有长相还不够，还得知道每个字段“是什么意思”。比如报文里有个字段写着 `200`，这到底代表“请求成功”，还是“网站作者欠你 200 块”？语义就是给每个字段、每一串比特赋予含义，让双方对同一串 0 和 1 有共同的理解。语义回答的问题是：“这串 0 和 1 在说什么？”

## <span style="color: rgb(var(--brand-dark));">1.6.6 时序（Timing）：什么时候说、说得快还是慢</span>

### 最后一个要素是时序，它规定了两件事：报文发送的*顺序*（先握手再传数据，不能一上来就狂飙），以及发送的*速度/节奏*（对方能接受多快，你就发多快）。就像两个人聊天，得等对方把话说完了你再接；要是抢话，或者对方还没准备好你就一通输出，对话就崩了。时序回答的问题是：“该什么时候说？”

## 所以，协议就是网络世界的“语言”和“法律”——它规定了大家怎么说话（语法）、说的是什么意思（语义）、以及什么时候该说（时序）。有了协议，不同厂商、不同系统的设备才能互联互通。下一节，我们就要给网络做“体检”了：带宽、流量与时延。
