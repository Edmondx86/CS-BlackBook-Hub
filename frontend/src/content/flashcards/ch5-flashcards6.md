# <span style="color: rgb(var(--brand));">SDN 控制平面</span>

### 传统路由器把“算路（控制平面）”和“转发（数据平面）”**焊死在同一个盒子里**。想改一下网络行为，就得一台一台登录进去敲命令，累死网管不说，还特别容易改错。于是有人提出了一个大胆的想法：**干脆把控制平面从路由器里抽出来，集中到一个控制器上**——这就是 **SDN（Software-Defined Networking，软件定义网络）**。前几张卡里 OSPF、BGP 那种“每台路由器自己算”的模式，到这里被彻底改写了。

# <span style="color: rgb(var(--brand-dark));">5.5 SDN 的四大特征</span>

### 教科书给 SDN 总结了四个标志性特征，缺一不可：

1. **基于流的转发（flow-based forwarding）**：转发不再只看目的 IP，而是可以按“源 IP + 目的 IP + 端口 + 协议 + ……”等字段的组合来匹配和转发，一条“流”可以拥有自己的专属规则。
2. **数据平面与控制平面分离**：路由器只保留“傻快傻快”的转发能力，算路的活儿统统交给外部控制器。
3. **控制平面在外部控制器**：一个（逻辑上）集中的控制器掌握全网视图，统一计算并下发转发表。
4. **可编程的网络**：控制器向上提供 API，路由、负载均衡、防火墙这些网络功能，都能像写软件一样“编程”实现。

### 核心好处一句话：**网络从“一台台手动配置的盒子”，变成“一个可编程的整体”**。改行为不用碰硬件，改改软件就行。

## <span style="color: rgb(var(--brand-dark));">架构：三层 + 两个接口</span>

### SDN 的分层架构可以自上而下这样理解：

* **最上层：网络应用**（路由、访问控制、负载均衡），它们只管提需求，不关心底层怎么实现。
* **中间：SDN 控制器**，维护全网状态，把上层的需求翻译成具体的流表规则。
* **最下层：受控的交换机 / 路由器**，只负责按流表把包转发出去。

### 连接这三层的是两个方向相反的接口：

* **南向接口（southbound API）**：控制器 → 设备，负责**下发流表**。最著名的协议就是 **OpenFlow**。
* **北向接口（northbound API）**：应用 → 控制器，提供**编程接口**（比如 RESTful API），让网络应用能读写控制器的状态。

### 这两条名字的来源其实很形象：把控制器想象成中间的大脑，向南（向下）对着设备发号施令，向北（向上）对着应用提供能力——方向感一下就清楚了。

## <span style="color: rgb(var(--brand-dark));">控制器与 OpenFlow 流表</span>

### **OpenFlow** 是南向接口的事实标准。控制器给每台交换机下发一张**流表（flow table）**，每条流表项由三部分组成：匹配字段、动作、计数器（计数器负责统计命中了多少分组和字节，方便监控与计费）。匹配和动作具体怎么写，我们在 4.4 节已经拆开讲过，这里重点看它带来的变化：**转发规则不再固化在硬件里，而是控制器随时可以改写的软件状态**。

### 一个包到达交换机后，就在流表里**按优先级逐条匹配**，命中哪条就执行哪条的动作（转发、丢弃、改写字段，或者上交给控制器）；如果一条都没命中，就交给**表缺失（table-miss）**条目处理——通常是发给控制器，让控制器当场决定该怎么办，甚至顺手把新规则装进流表。这种“拿不准就问大脑”的机制，正是网络可编程的关键。

## <span style="color: rgb(var(--brand-dark));">SDN vs 每路由器控制</span>

### 把两种控制平面摆在一起对比，感受会更深：

* **每路由器控制**：分布式、各自为政，就像没有红绿灯的路口，司机们自己商量着走——能走，但全凭默契。
* **SDN 控制**：逻辑集中、全局调度，就像一个交通大脑统一指挥全城红绿灯——看得全，也调得动。

### SDN 的优势在于**全局视角 + 快速灵活**，流量工程、负载均衡、访问控制都可以直接在控制器上实现；代价是控制器本身成了“单点”，所以工程上会用集群做高可用，同时还要依赖 OpenFlow 这类南向协议作为设备之间的统一语言。

## 所以，SDN = 把控制平面集中起来、用软件编程网络。它让网络像软件一样可修改、可自动化，是云计算时代数据中心网络的基石。搞懂了 SDN，你也就看懂了“未来网络”大概长什么样。不过网络世界不只有“怎么把包送到”，还有“出了事找谁报信”——下一张卡我们就去看网络层的那位报信员：ICMP。
