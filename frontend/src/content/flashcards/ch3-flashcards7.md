# <span style="color: rgb(var(--brand));">TCP 拥塞控制</span>

### 上一节说了，因特网选的是“端到端”拥塞控制，TCP 只能靠“丢包/超时”来**猜**网络堵不堵。这一节就看 TCP 具体怎么猜、怎么调——这套算法就是让千千万万个 TCP 连接在一条链路上“不打架、都吃好”的关键。

# <span style="color: rgb(var(--brand-dark));"> 3.7.1 慢启动：先试探着走 </span>

### TCP 维护一个**拥塞窗口（Congestion Window, cwnd）**，限制“已发送但未确认”的数据量。刚开始不知道网络能扛多少，就**从 1 个 MSS（最大报文段）起步**，每收到一个 ACK 就把 cwnd 翻倍：

> cwnd：1 → 2 → 4 → 8 → 16 ……（指数增长）

### 这种指数级的“试探”就叫**慢启动（Slow Start）**——名字叫“慢”，其实长得飞快，是为了快速找到网络能力的上限。

# <span style="color: rgb(var(--brand-dark));"> 3.7.2 拥塞避免：线性爬升 </span>

### 等 cwnd 涨到一个阈值 **ssthresh** 后，就不能再翻倍了，否则分分钟把网络打爆。于是进入**拥塞避免（Congestion Avoidance）**阶段：每过一个 RTT，cwnd 只 **+1 个 MSS**——线性、温和地增长。

### 这种“先指数、后线性”的节奏，加上遇到丢包时的**乘性减半（cwnd 直接砍半）**，合起来就是鼎鼎大名的 **AIMD**：

> **A**dditive **I**ncrease（加法增） + **M**ultiplicative **D**ecrease（乘法减）

# <span style="color: rgb(var(--brand-dark));"> 3.7.3 快重传 & 快恢复 </span>

### 丢包了怎么办？TCP 有两种“察觉”方式：

* **超时**：最重的一招，说明可能堵得很严重 → cwnd 打回 1，重新慢启动。
* **3 个重复 ACK**：收到 3 个相同的 ACK，说明“后面某个包丢了，但后面还有包陆续到达”——这时网络还没完全堵死，于是用**快重传**：不傻等超时，立刻重传那个丢失的包，然后**快恢复**：cwnd 只减半，进入拥塞避免，而不是打回 1。

# <span style="color: rgb(var(--brand-dark));"> 3.7.4 经典算法与公平性 </span>

### 历史上两个经典版本：

* **TCP Tahoe**：无论超时还是 3 个重复 ACK，一律 cwnd 打回 1 重新慢启动（保守）。
* **TCP Reno**：3 个重复 ACK 走快恢复（cwnd 减半），只有超时才打回 1（现代主流）。

### 最后的**公平性**：如果有 N 条 TCP 连接共享同一瓶颈链路，AIMD 这套“加则同加、减则同减”的机制，会让它们最终**收敛到大致均分带宽**——谁也别想长期多吃多占。这正是互联网至今还能“大体和谐”运行的秘密之一。
