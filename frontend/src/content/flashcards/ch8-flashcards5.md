# <span style="color: rgb(var(--brand));">TLS：保护 TCP 连接</span>

### 前面几张卡讲的都是“零件”：加密、哈希、签名、证书、鉴别。现在到了组装环节——把这些零件拼成一套真正能用的协议，让浏览器和服务器之间的 HTTP 通信变得安全。这套协议就是 `TLS（Transport Layer Security）`，它的前身是你更熟悉的 `SSL`。你每天访问的 HTTPS 网站，背后跑的就是它。

# <span style="color: rgb(var(--brand-dark));">8.6 保护 TCP 连接：TLS</span>

## <span style="color: rgb(var(--brand-dark));">TLS 站在哪里</span>

### 一句话说明它的位置：`TLS 夹在应用层和 TCP 之间`。

* 对应用层来说，它就像一条普通的 TCP 连接——HTTP 只管往里面写请求，然后读响应，完全不知道底下在加密。
* 对 TCP 来说，它就是一个普通的应用，发的还是普通的字节流。

### 所以 `HTTPS 本质上就是“HTTP over TLS”`：HTTP 那一堆方法、状态码、Cookie 全部原封不动，只是传输过程被包了一层。这也是为什么给网站加 HTTPS 不需要重写业务代码——**换个端口（443）、加个证书就行**。

## <span style="color: rgb(var(--brand-dark));">握手：四次交互建立信任</span>

### TLS 最核心的部分是`握手（handshake）`，目标有三个：**协商算法、鉴别服务器、生成会话密钥**。大致分四步：

1. `客户端问好（ClientHello）`：浏览器说“我支持这些加密算法、这些哈希算法，这是我生成的一个随机数 nonce。”
2. `服务器回应（ServerHello）`：服务器从里面挑一套算法，附上自己的随机数，然后`出示自己的证书`——证书里带着它的公钥，并由 CA 签名。
3. `验证并生成密钥`：浏览器验证证书链（这条链最终要能追溯到自己内置的根证书），确认“这把公钥确实属于这个域名”。然后客户端生成一个`前主密钥（PMS）`，用`服务器公钥加密`后发过去。此时双方各有两个随机数加一个 PMS，用同样的算法一算，就得到了`共享的主密钥（MS）`。
4. `确认握手完成`：双方用 MS 派生出后续通信所需的密钥，并交换一段用新密钥加密的“完成”消息，确认两边算出的密钥一致、握手没被中间人篡改。

### 为什么要用`两个随机数 + PMS` 凑出主密钥，而不是直接用 PMS？因为`随机数的存在保证了每次会话的密钥都不同`——即使 PMS 泄露一次，也只影响那一次会话，无法解密历史流量。这叫做`前向保密（forward secrecy）`。

### 从主密钥会派生出`四把密钥`，各管一摊：

* `客户端写密钥`：客户端加密、服务器解密
* `服务器写密钥`：服务器加密、客户端解密
* `客户端 MAC 密钥`：客户端发数据时算 MAC 用
* `服务器 MAC 密钥`：服务器发数据时算 MAC 用

### 注意“写密钥”是`分方向`的——TCP 是全双工，两个方向各用各的密钥，互不干扰。

## <span style="color: rgb(var(--brand-dark));">记录协议：真正在干活的部分</span>

### 握手把钥匙配好了，接下来 `TLS 记录协议（record protocol）` 负责实际的数据传输，它做三件事：

1. `分段`：把上层交下来的字节流切成不超过约 16 KB 的片段。
2. `算 MAC`：为每个片段计算`报文鉴别码`，保证完整性（防止 Trudy 篡改传输中的数据）。
3. `加密`：把“片段 + MAC”一起加密，交给 TCP 发出去。

### 接收端反过来做一遍：解密 → 验证 MAC → 重组 → 交给应用层。整个过程对 HTTP 完全透明。

## <span style="color: rgb(var(--brand-dark));">TLS 1.3：更快也更简</span>

### 2018 年定稿的 `TLS 1.3` 做了两件重要的事：

* `砍掉不安全的旧算法`：RSA 密钥传输、RC4、SHA-1 等一律删除，只保留经过验证的强算法，从根本上减少了降级攻击的空间。
* `简化握手`：把原来两个往返的握手压缩到`一个往返`，并支持 `0-RTT`（对之前连接过的服务器，可以在第一个报文里就带上数据）。这对移动网络下的首屏加载速度提升非常明显。

## 所以，TLS 就是把前面所有安全零件组装起来的“成品”：**握手用证书和公钥加密解决鉴别与密钥分发，记录协议用对称加密和 MAC 解决机密性与完整性**。理解了它，你也就理解了为什么浏览器地址栏里那个小锁头，背后是一整套精密的协议在支撑。
