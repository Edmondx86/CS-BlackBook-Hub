# <span style="color: rgb(var(--brand));">网络管理：SNMP</span>

### 想象你是某大厂的网管，手底下管着成千上万台路由器、交换机、服务器。你怎么知道哪台设备挂了、哪条链路堵了、哪台机器的 CPU 快爆了？总不能一台台跑过去敲 `ping` 吧。这就需要`网络管理（network management）`——一套用来监控、配置、排障网络设备的体系，其中最经典的协议就是 `SNMP`。

# <span style="color: rgb(var(--brand-dark));">5.7.1 网络管理的五大构件</span>

### 一个完整的网络管理体系由五块拼图组成，缺一块都转不起来：

1. **管理者（managing server）**：网络管理员操作的“控制中心”，负责发起查询、接收告警，通常就是一台跑着网管软件的服务器。
2. **被管设备（managed device）**：被监控的路由器、交换机、主机等网络设备。
3. **被管对象（managed object）**：设备里那些可以被监控、被配置的变量，比如接口流量、CPU 占用率。
4. **管理代理（agent）**：跑在设备上、替管理者“跑腿”收集和修改数据的软件。
5. **网络管理协议**：管理者和代理之间沟通用的语言，最经典的就是 `SNMP`。

### 顺口记成一句话：**管理者下命令，代理去执行，协议管通信**。而被管对象是怎么组织的，就要看下面这个 MIB。

# <span style="color: rgb(var(--brand-dark));">5.7.2 监控：SNMP 的轮询与陷阱</span>

### **SNMP（Simple Network Management Protocol，简单网络管理协议）** 采用“管理者—代理”模型，日常通信有两种典型方式：

* **轮询（polling / request-response）**：管理者**主动**向代理发请求（“你现在的接口流量是多少？”），代理查一下 MIB 再回答。管理者可以周期性地轮询一批设备，从而掌握全局状态。
* **陷阱（trap）**：反过来，当设备发生异常（接口 down 了、温度过高），代理**主动、立刻**给管理者发一条“陷阱”消息告警——不用等管理者来问，出了事马上报。

### 一个形象的比喻：轮询就像班主任**定期点名**，挨个问“到没到”；陷阱就像学生**主动举手打报告**，“老师，我发烧了！”。

## <span style="color: rgb(var(--brand-dark));">MIB：被管对象的“身份证”</span>

### SNMP 里，所有被管对象都组织成一棵`管理信息库（Management Information Base, MIB）`树，每个对象用一串数字唯一定位——比如 `1.3.6.1.2.1.1.3` 就表示“系统运行时间”。管理者就是靠这些“身份证号”来读写设备状态的，所以命名规则必须全网统一，否则代理和管理者根本对不上话。

### 顺带一提，MIB 只规定了“数据长什么样”（用 SMI 这套描述语言定义），并不规定怎么传——传输的活儿是 SNMP 协议自己的事。把“数据定义”和“数据传输”分开，是这套体系设计上比较聪明的一点。

## <span style="color: rgb(var(--brand-dark));">三个版本的安全性</span>

### SNMP 有 v1、v2c、v3 三个主要版本：前两个基本靠明文口令（community string）认证，谁截到谁就能读；**SNMPv3 才加入加密与认证**，安全性才算真正上了台面。所以现在新部署的网络，基本都直接用 v3。

# <span style="color: rgb(var(--brand-dark));">5.7.3 配置：更现代的 NETCONF / YANG</span>

### SNMP 擅长*监控*，但在*配置*设备这件事上相当笨拙——它一次只能读写一个标量变量，想配一条稍微复杂的策略就得来回折腾几十次。于是有了更现代的组合：

* **YANG**：一种数据建模语言，用来**描述**设备的配置与状态数据长什么样，相当于给配置定了一份“说明书模板”。
* **NETCONF**：一套基于 XML 的协议，按 YANG 定义好的模型，对设备做**结构化、可编程的配置管理**。

### 如果说 SNMP 是“打电话口头吩咐”，那 NETCONF/YANG 就像“发一份格式规范的配置清单”——事务化、能校验、可回滚，还特别契合 SDN 时代“可编程网络”的理念。

## 所以，网络管理就是“怎么照看一大群网络设备”：SNMP 负责`监控`（轮询 + 陷阱），NETCONF/YANG 负责`配置`。有了它们，网管才能从到处救火的消防员，升级成运筹帷幄的指挥官。
