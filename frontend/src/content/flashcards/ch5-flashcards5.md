# <span style="color: rgb(var(--brand));">域间路由：BGP</span>

### OSPF 解决了“一个自治系统（AS）内部怎么指路”，那 AS 与 AS 之间呢？电信、联通、移动、各家云厂商、跨国公司的网络各自为政，谁该把流量交给谁、又该收谁的钱？这就是域间路由（inter-AS routing）的活儿，主角是 <strong>BGP（Border Gateway Protocol，边界网关协议）</strong>——它常被称作“把整个因特网粘合在一起的胶水”。

# <span style="color: rgb(var(--brand-dark));">5.4 BGP：交换的是可达性，不是最短路径</span>

### 先纠正一个常见误解：BGP 的核心任务不是算最短路径，而是在 AS 之间交换“可达性信息”——告诉邻居：“我能到达某个网络前缀（比如 202.120.224.0/20），经过我走就行。”这里的“前缀”就是我们 4.3.2 见过的 CIDR 地址块。

### 扮演关键角色的是边界路由器（gateway router）：它位于 AS 边缘，通过一条 TCP 连接（端口 179） 与相邻 AS 的边界路由器建立 BGP 会话，在上面持续地通告新路由、撤销失效路由。注意，BGP 会话是半永久的，一旦建立就长期维持，属于典型的“长连接”。

### BGP 有两种形态，别搞混：

* eBGP（external BGP）：跑在不同 AS 之间，负责从外部“学”到路由。
* iBGP（internal BGP）：跑在同一 AS 内部，负责把从外部学到的路由“传”给本 AS 的其他路由器。

### 一句话：eBGP 对外吹风，iBGP 对内传话。典型流程是——边界路由器用 eBGP 从邻居 AS 学到一条路由，再用 iBGP 把它散布到本 AS 内部，最终让 AS 里每台路由器都知道“去那个网络该找谁”。

## <span style="color: rgb(var(--brand-dark));">两个关键属性：AS-PATH 与 NEXT-HOP</span>

### BGP 的路由通告里带着若干路径属性（path attributes），其中最重要的两个是：

* `AS-PATH`：这条路由经过的所有 AS 编号列表，比如 `AS3 AS2 AS1`。它身兼两职——一是防环，如果收到的通告里已经包含自己的 AS 号，说明绕回来了，直接丢弃；二是选路依据，一般路径越短越优先。
* `NEXT-HOP`：这条路由的下一跳是谁，通常是相邻 AS 边界路由器的接口 IP 地址。它告诉本 AS 内部的路由器：“想去那个前缀，先把包交给这个地址。”

### 正因为通告里带着完整路径、而不是仅仅一个距离，BGP 也被叫作路径向量（path-vector）协议——距离向量只带“多远”，它把“怎么走”也一起带上了，防环能力天然更强。

## <span style="color: rgb(var(--brand-dark));">选路：策略永远排在性能前面</span>

### 这是 BGP 与 OSPF 最本质的区别：OSPF 追求“代价最小的路”，而 BGP 追求“符合商业策略的路”。BGP 的选路大致按下面的优先级逐条筛：

1. 本地偏好（local preference）：AS 内部管理员设的“最喜欢哪条路”，这是最硬的一条，通常直接体现商业关系。
2. 最短 AS-PATH：偏好经过 AS 更少的路由。
3. 热土豆路由（hot potato routing）：前两条打平的情况下，选本 AS 内部到 NEXT-HOP 代价最小的那个出口——恨不得赶紧把这个包甩出去。
4. BGP 标识符：实在还平，就比路由器 ID，用最笨的办法打破平局。

### 热土豆路由值得多说一句：一个 AS 收到发往外网的分组后，只想**尽快、就近地把它扔给下一个 AS**，哪怕这样整体路径更长也无所谓——反正出了我的网，开销就是别人的了。是不是很有“烫手山芋赶紧丢”的甩锅味道？

### 而决定“要不要通告、要不要采用”的，是 AS 之间的商业关系：

* 客户-提供商（customer-provider）：客户付费买接入，提供商自然乐于帮客户转发流量。
* 对等（peer）：两家 AS 互免费用，交换彼此及各自客户的流量，但不会替对方转发第三方的流量。
* 提供商-提供商：一般不通告，因为谁也不愿意白干活。

### 这就是为什么在 BGP 的世界里，**钱和关系排第一，性能只能排第二**。

## <span style="color: rgb(var(--brand-dark));">域内与域间，正面比一比</span>

| 维度 | 域内（OSPF） | 域间（BGP） |
| --- | --- | --- |
| 关注点 | 性能：最短、最快 | 策略：商业关系与结算 |
| 作用范围 | 单个 AS 内部 | AS 之间 |
| 核心算法 | 链路状态 + Dijkstra | 路径向量（基于 AS-PATH） |
| 交换内容 | 链路状态（拓扑） | 可达性（网络前缀 + 路径） |
| 管理主体 | 同一机构 | 多个互相独立的机构 |

## 所以，BGP 是“自治系统之间”的路由协议：它不追求全局最短路，而是靠 AS-PATH 防环、靠商业策略选路，让全球因特网既能互联互通、又能各自为政。可以说，没有 BGP，就没有跨运营商的互联网。
