# <span style="color: rgb(var(--brand));">电子邮件系统 (SMTP / IMAP)</span>

### 在微信、QQ 这些即时通信大行其道的今天，电子邮件（Email）看起来像个“老古董”，但它可是因特网元老级的应用，几十年来格式一直没大变。而且它和 Web 有个本质区别：Web 是“你主动去取”（拉），邮件是“别人主动塞给你”（推）。这一节就拆开看看，一封邮件是怎么从你的“发送”按钮，飞进对方邮箱的。

# <span style="color: rgb(var(--brand-dark));"> 2.6 电子邮件的三大组件 </span>

### 整个邮件系统由三样东西搭起来，缺一不可：

1. `用户代理（User Agent, UA）`：就是你和邮件打交道的那个界面，比如 Outlook、Foxmail、苹果“邮件”，或者浏览器里的 Gmail/QQ 邮箱网页。你用它写邮件、看邮件、存邮件，它是“收发室窗口”。
2. `邮件服务器（mail server）`：每封邮件都得住在一个“邮箱”里，这个邮箱就在邮件服务器上。每个收件人的服务器上有个“邮箱”专门放别人发来的信。如果对方没收到，多半是信还在邮件服务器的“发送队列”里排队，或者被退回了。
3. `简单邮件传输协议（SMTP）`：负责把邮件“推”出去的那个协议。注意，SMTP 只管“发送”，不管“收取”，后面再细说。

### 简单捋一遍流程：你用 UA 写好邮件 → 你的邮件服务器用 SMTP 把它“推”到对方的邮件服务器 → 对方用他的 UA 去自己的邮件服务器上“拉”下来读。这“一推一拉”，就是邮件系统的灵魂。

## <span style="color: rgb(var(--brand-dark));"> 2.6.1 SMTP：只管“推”的老邮差 </span>

### SMTP（Simple Mail Transfer Protocol）是邮件系统的核心传输协议，端口号是 `25`，它跑在 `TCP` 之上，可靠传输。它的工作方式很“老派”：

1. `面向连接`：就像寄信前先打个电话确认对方在不在，SMTP 先建立 TCP 连接，再开始“对话”。
2. `只用 7 位 ASCII`：这是 SMTP 最大的“臭毛病”——它当年只能传英文文本，中文、图片、附件这些“二进制”东西直接塞进去会乱码。后来才靠 MIME（多用途因特网邮件扩展）把这些二进制数据“伪装”成 ASCII 才能传。
3. `推（push）`：SMTP 是“发送方把信塞给接收方”，从发送方邮件服务器一路推到接收方邮件服务器。

### 拿 SMTP 和 HTTP 对比一下很有意思：两者都跑在 TCP 上，都是 ASCII 报文，但**HTTP 是“拉”（pull），SMTP 是“推”（push）**；HTTP 请求一个对象，一个响应就完了，SMTP 却是一段多回合的“对话”；还有 SMTP 要求报文必须是 7 位 ASCII，而 HTTP 没这个限制。

## <span style="color: rgb(var(--brand-dark));"> 2.6.2 邮件报文格式与 MIME </span>

### 一封邮件从“信封”到“信纸”分三层：

1. `信封（envelope）`：负责运输的“快递单”，上面写着寄件人、收件人，但这层信息是 SMTP 私下看的，用户一般见不到。
2. `首部行（header lines）`：我们能看到的那部分，比如 `From:`（谁发的）、`To:`（发给谁）、`Subject:`（主题）。这些是“门面信息”。
3. `邮件体（body）`：真正的正文，写你想说的话。

### 前面提到 SMTP 只能传 ASCII，那中文邮件、图片附件怎么活下来的？靠的就是 **MIME（Multipurpose Internet Mail Extensions，多用途因特网邮件扩展）**。它在邮件首部里加了几行声明，把二进制数据重新编码成 ASCII，这样 SMTP 就能“蒙混过关”地把图片、视频、中文统统传过去，接收端再用 MIME 还原成原来的样子。

## <span style="color: rgb(var(--brand-dark));"> 2.6.3 收取协议：POP3、IMAP 与 HTTP </span>

### SMTP 负责“推”到对方服务器，但对方“怎么把信拿回家读”，是另一套协议的事。这就是“拉”协议登场的地方，主要有两位选手：

1. `POP3（邮局协议第 3 版）`：简单粗暴。用户用 UA 连上邮件服务器，把所有邮件一股脑“下载”到本地，然后（通常）就把服务器上的删了。适合“一台电脑用到底”的人，缺点是换台设备就看不到以前的信了。
2. `IMAP（因特网邮件访问协议）`：聪明得多。邮件一直保存在服务器上，用户只是“远程查看”。你在手机上读了，在电脑上也显示已读，所有设备看到的都是同一份“云端”状态。缺点是服务器得替你存邮件，占用空间。
3. `基于 Web 的邮件（HTTP）`：也就是 Gmail、QQ 邮箱网页版那套，用户和邮件服务器之间用 HTTP 通信。注意：这只是“读邮件”这一环换成了 HTTP，服务器之间转发邮件靠的还是 SMTP。

### 所以记住一个关键区别：**SMTP 是“推”，POP3/IMAP/HTTP 是“拉”**。前者负责把信送到对方门口，后者负责让对方把信取进屋里。到这里，电子邮件这套“老系统”就讲透了。下一张卡，我们回到“可扩展性”这个 C/S 架构的痛点上——看看 P2P 是怎么解决“文件太大、下载的人太多，服务器被挤爆”这个难题的。
