# <span style="color: rgb(var(--brand));">MAC 地址与 ARP</span>

### 我们已经知道 IP 地址能让数据报跨过千山万水找到目的主机。但最后一跳呢？数据报到了目的子网，路由器怎么知道**该把帧交给哪一块网卡**？答案是需要第二套地址——**MAC 地址**，以及一个把 IP 地址翻译成 MAC 地址的协议——**ARP**。这一对搭档，就是局域网内部寻址的全部秘密。

# <span style="color: rgb(var(--brand-dark));">6.4.1 链路层地址与 ARP</span>

## <span style="color: rgb(var(--brand-dark));">为什么需要两套地址</span>

### 你可能会问：光有 IP 地址不就够了？不行。原因有两层：

* **IP 地址是“逻辑、分层”的**：它标识的是“哪台主机在哪个网络里”，随着设备换网络而变化，作用范围是**全球**。
* **MAC 地址是“物理、扁平”的**：它标识的是**一块具体的网卡**，烧在适配器里，理论上全球唯一且**终身不变**，作用范围只在**同一段链路**内。

### 打个比方：IP 地址像“某市某区某街道几号”，负责把你带到那栋楼；MAC 地址像“身份证号”，负责在楼里认出具体是哪个人。**网络层负责跨网络，链路层负责同一段链路**——分工明确，缺一不可。

### 所以一趟跨网络的旅程是这样的：源主机把帧发给**第一跳路由器的 MAC 地址**（而不是目的主机的），路由器拆开、查表、再把帧发给下一跳的 MAC 地址……MAC 地址每一跳都在换，IP 地址始终不变。

## <span style="color: rgb(var(--brand-dark));">ARP：把 IP 翻译成 MAC</span>

### **ARP（Address Resolution Protocol，地址解析协议）** 干的就是这件事：给定一个同一子网内的 IP 地址，查出它对应的 MAC 地址。流程非常朴素：

1. **广播请求**：源主机在本子网内广播一个 ARP 查询——“谁的 IP 是 192.168.1.5？请把你的 MAC 地址告诉我。”因为不知道对方在哪，只能广播。
2. **单播应答**：只有 IP 匹配的那台主机回应，用**单播**把自己的 MAC 地址送回去。
3. **缓存**：源主机把这个映射存进 **ARP 表**，并设置大约 20 分钟的老化时间，之后再用就直接查表，不用再广播。

### 这里有个容易踩的坑：**ARP 只在同一个子网内工作**。如果目的主机在另一个子网，源主机查到的其实是**默认网关（第一跳路由器）的 MAC 地址**——先把帧交给路由器，剩下的路由再操心。

### 顺便说一句，`arp -a` 这个命令就能看到你本机的 ARP 表，里面写满了“IP → MAC”的映射关系，感兴趣的可以自己敲一下看看。

## 所以，MAC 地址负责“这一段链路上是谁”，ARP 负责“把 IP 换成 MAC”，两者合起来解决了局域网内部的最后一跳寻址。记住那句话：**IP 地址带你到楼，MAC 地址带你到人。**
