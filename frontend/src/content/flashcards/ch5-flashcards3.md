# <span style="color: rgb(var(--brand));">距离向量路由算法</span>

### 上一张卡的链路状态算法要“广播全网”，像个十足的社牛，开销不小。**距离向量（Distance-Vector, DV）算法**则是个彻底的社恐——它**只跟自己的直接邻居唠嗑**：把自己的距离表告诉邻居，邻居再告诉它的邻居，像传八卦一样逐跳把信息泡遍全网。它背后的数学支柱，是 **Bellman-Ford 方程**。

# <span style="color: rgb(var(--brand-dark));">5.2.2 距离向量（DV）算法</span>

## <span style="color: rgb(var(--brand-dark));">Bellman-Ford：一条式子打天下</span>

### 距离向量的全部精髓，就浓缩在这一行里：

> `d_x(y) = min_v { c(x,v) + d_v(y) }`

### 翻译成人话：**我到 y 的距离，等于“我到某个邻居 v 的代价”加上“邻居 v 到 y 的距离”，在所有邻居里取最小的那个**。换句话说，我想去 y，不自己瞎猜，而是挨个问邻居：“从你这儿走要多久？”然后挑一个总账最划算的。

### 每个节点维护一张**距离向量表**，记录“我到每个目的地大概多远”，并**定期**把它发给所有直接邻居；邻居收到后用上面的式子更新自己的表，再把更新结果传下去。如此反复迭代，全网最终会收敛到真实的最短距离。

### 这就像玩传话游戏：你只知道“隔壁老王说他离火车站 10 分钟”，而你到老王家要 2 分钟，于是推断“我离火车站大概 12 分钟”。你压根没去过火车站，却靠邻居的二手信息估出了距离——Bellman-Ford 的威力就在这儿。

### 还有个关键细节值得记一笔：DV 算法是**异步、迭代、分布式**的。它不需要全局时钟，也不需要谁掌握全网拓扑，每个节点只管闷头跟邻居对账，收敛是“涌现”出来的。

## <span style="color: rgb(var(--brand-dark));">无穷计数：好消息传得快，坏消息传得慢</span>

### DV 有个臭名昭著的毛病：链路代价变小时，好消息一两轮就传遍全网；可一旦某条链路**断了**，这个坏消息要磨蹭很久才能被“消化”，甚至陷入**无穷计数（count-to-infinity）**的死循环。

### 经典例子：A—B—C 串成一列，B 到 C 的代价是 1。突然 B 和 C 之间的链路断了。此时 A 还傻乎乎地告诉 B：“我到 C 只要 2（经过你）”；B 一算：“咦，A 到 C 才 2，那我走 A→B→C 岂不是 3？比我手里的 ∞ 强多了”，于是把自己的距离改成 3，又回头告诉 A；A 收到后更新成 4，再告诉 B……**两个路由器互相喂假消息，距离越滚越大**，一路慢慢爬到“无穷”。

### 缓解办法里最出名的是**毒性逆转（poisoned reverse）**：如果 B 是“经过 A”才到达 C 的，那 B 在跟 A 通信时就故意谎称“我到 C 是 ∞”，堵死 A 绕回来的念头。此外还有**水平分割**（不把从某个邻居学来的路由再通告回该邻居）和**定义最大代价**（超过阈值就视为不可达）等辅助手段。不过毒性逆转只能治标，一旦环路涉及三个以上节点就会失效。

## <span style="color: rgb(var(--brand-dark));">两种算法正面对决</span>

### 把 LS 和 DV 摆在一起，各自的取舍一目了然：

| 维度 | 链路状态（LS） | 距离向量（DV） |
| --- | --- | --- |
| 信息来源 | 洪泛全网拓扑 | 只和直接邻居交换 |
| 计算方式 | 每个节点独立跑 Dijkstra | 分布式迭代（Bellman-Ford） |
| 收敛速度 | 快 | 慢，可能无穷计数 |
| 通信开销 | 大（广播到全网） | 小（只发给邻居） |
| 环路风险 | 低 | 较高，需毒性逆转等补丁 |

### 现实中的对应也很清楚：OSPF 走的是链路状态路线，而老牌的 RIP 走的是距离向量路线。下一张卡，我们就去看 OSPF 这个“域内路由”的实际选手。

## 所以，距离向量 = 只问邻居、迭代传话。它用极小的开销换来了简单与可扩展，代价是坏消息传得慢——这个“分布式算法收敛慢”的教训，是理解所有路由协议的关键一课。
